# AI-помощник для подготовки товарных описаний

MVP-сервис для генерации черновика карточки контрольно-измерительного прибора для B2B-интернет-магазина.

Основной LLM-провайдер — **GigaChat API**. Проект также содержит `mock`-провайдер для тестов интерфейса без внешнего API.

## Что реализовано

- веб-форма и `POST /api/generate`;
- GigaChat API через официальный Python SDK;
- Structured Output по JSON Schema;
- SEO-заголовок до 70 символов;
- SEO-описание 800–1200 символов;
- 3–5 поисковых запросов;
- commercial-блок;
- список отсутствующих данных;
- обработка некорректного JSON и ошибок API;
- серверная проверка ответа;
- mock-режим для тестов.

## Защита от выдуманных характеристик

`key_characteristics` вообще не генерируется LLM. Приложение формирует список напрямую из входного `specs`. Пустое значение превращается в `данных нет`.

После генерации дополнительно проверяются числовые значения: если модель добавила число, которого не было во входном JSON, результат отклоняется. Сервис может выполнить повторную генерацию; всего допускается до трёх попыток.

## Установка

```bash
python -m venv venv
source venv/Scripts/activate
pip install -r requirements.txt
cp .env.example .env
```

## Получение ключа GigaChat

1. Создать проект GigaChat API в личном кабинете Studio.
2. Открыть **Настройки API**.
3. Нажать **Получить ключ**.
4. Скопировать **Authorization Key** и сохранить его в `.env`.

Ключ нельзя коммитить в Git.

## `.env`

```env
LLM_PROVIDER=gigachat
GIGACHAT_CREDENTIALS=
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_BASE_URL=https://api.giga.chat/v1
GIGACHAT_MODEL=GigaChat-3-Ultra
GIGACHAT_VERIFY_SSL=false
GIGACHAT_TIMEOUT=120
```

Для физического лица используется `GIGACHAT_API_PERS`.

### SSL

Для локального MVP `GIGACHAT_VERIFY_SSL=false` позволяет тестировать приложение без системной установки сертификатов НУЦ Минцифры. Для production проверку SSL следует включить и сертификаты настроить корректно.

## Усиленная защита от галлюцинаций

Сервис использует несколько уровней защиты:

1. **Реестр разрешённых фактов.** Из `name`, `manufacturer`, `description` и непустых `specs` создаётся явный список фактов. Модели запрещено использовать внешние знания о типе прибора.
2. **Характеристики не генерируются LLM.** Они копируются напрямую из `specs`.
3. **Детерминированная проверка чисел.** Новые числовые значения приводят к отклонению ответа.
4. **Отдельный факт-чекер.** После генерации второй запрос к модели проверяет каждое утверждение только относительно реестра фактов. Неподтверждённый текст автоматически отправляется на перегенерацию.
5. **Fail closed.** Если после трёх попыток полностью подтверждённый текст получить не удалось, сервис возвращает ошибку и просит добавить исходные данные вместо публикации сомнительного текста.

Например, из факта «предназначен для измерения избыточного давления» нельзя вывести «используется на промышленных предприятиях» или «для трубопроводов». Такие расширения должны быть отклонены факт-чекером.

## Безопасность API-ключа

`GIGACHAT_CREDENTIALS` хранится только в локальном `.env`. В репозиторий попадает только `.env.example` с пустым значением. `.gitignore` исключает `.env`, варианты `.env.*`, ключи и PEM-файлы.

Перед публикацией репозитория рекомендуется выполнить:

```bash
git check-ignore .env
python scripts/check_secrets.py
git status
```

Если `.env` когда-либо уже был добавлен в Git, одного `.gitignore` недостаточно:

```bash
git rm --cached .env
```

После этого секрет следует перевыпустить у провайдера, если он когда-либо попадал в коммит, скриншот или публичный лог.

Сырые исключения GigaChat API не отправляются в браузер: пользователь получает нейтральное сообщение без содержимого заголовков запроса и credentials.

## Ограничения

- автоматическая проверка снижает риск галлюцинаций, но не гарантирует отсутствие всех семантических ошибок;
- качество результата зависит от полноты исходных данных;
- финальный текст должен проверяться контент-менеджером;
- нет БД, CMS и деплоя — это сознательно вне MVP;
- в исходных материалах был приведён один конкретный товар; `examples/demo_missing_data.json` — синтетический пример для демонстрации обработки неполных данных.
